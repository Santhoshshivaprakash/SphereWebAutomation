Create Account — how the script works

tests/create-account.spec.ts · signs up a brand-new learner end to end, reading the real OTP from the inbox

The whole thing at a glance

Six screens, in this order. Everything after is detail.

1 · Pick language→ 2 · Personal details→ 3 · Confirm name→ 4 · Enter OTP→ 5 · Terms & conditions→ 6 · Logged in ✓

Step by step

The box on the left is what the browser shows. The text beside it is what the script does there, and why.

Before anything
Make a throwaway identity
  • email: stage-testauto48213@yopmail.com
  • phone: 9999999999
  • name: Test Aastrika
  • password: Sunbird@123

0A fresh address every run. Five random digits make the address unique, so the same signup can run again tomorrow without "this email already exists".

The environment is stamped into the name — stage- on staging — so you can tell at a glance where an account was born. Addresses are capped at 19 characters before the @.

That cap is not cosmetic. The portal rejects a longer local part, and it fails silently — the wizard just resets to a blank form, which looks like a button that never got clicked.

1Pick a language, then continue. The script also proves the rules of this screen: Next stays disabled until something is chosen, and picking one language unselects the other.

Screen 2
Personal details
  • First name · Last name
  • Email or phone
  • Sign in by: OTP / Password

2Fill the form and choose how to sign in. Before submitting, the script checks the empty-field rules so a broken form is caught here rather than three screens later.

Two paths exist and both are tested: email + OTP (the main one) and phone + password.

If the portal says the phone already exists, the script bumps the number by one and retries, rather than failing — 9999999999 is shared by many test runs.

Screen 3
"Is this your name?"
  • Test Aastrika
  • Confirm name

3A modal interrupts before the OTP is sent. It must be confirmed or nothing is emailed, so the script clicks it and only then waits for the OTP screen.

▼
Screen 4
Enter the 6-digit OTP
  • six boxes
  • Resend OTP
  • Verify

4The script reads the real email. No shortcut and no fixed code: it opens the throwaway inbox, finds the message, pulls the six digits, types them in. See the ladder below for how it copes when the inbox is slow.

The code is matched by its context in the message, not by "the first six digits" — otherwise it would happily type the year, 2026, into the box.
▼
Screen 5
Terms of Use
  • the T&C text

5Accept the terms. A new account lands here first; until it is accepted the learner cannot reach any real page, so an unaccepted account looks "logged in but broken".

▼
Screen 6
Signed-in home ✓
  • search bar in the header

6Proof, not assumption. The run only passes when the signed-in home actually renders — the header search box is the giveaway, since the public page has a "Log in" button instead.

The live session is then saved to disk so other scripts can run as this brand-new learner.

Getting the OTP — three ways, in order

Each is tried only if the one above it fails, so a slow or blocked inbox does not end the run.

1 · Inbox APIeasy-yopmail over HTTP
Fastest — asks the mail service directly, no browser involved. Works almost every time.
2 · Inbox in a second tabreads the message on screen
When the API is unavailable, a second browser tab opens the inbox and reads the message like a person would.
3 · OTP servicethe project's own endpoint
Last resort. If all three fail, the run stops and says the OTP never arrived — rather than typing a guess.
Each attempt polls and waits; mail takes a few seconds to land. Consecutive signups are also spaced apart deliberately, so a burst of runs doesn't get throttled by the mail service.

Signup accounts are OTP-only — they never get a password. That saved session is the only way to run as one, which is why it is written to disk at the end.

Running it

cd D:\Automation\SphereWebAutomation

# watch it happen (staging)
$env:BASE_URL="https://portal-staging.aastrika.org"
npx playwright test tests/create-account.spec.ts --project=Chrome --headed

# just mint a user and save the session (the last step only)
npm run mint:fresh-user
